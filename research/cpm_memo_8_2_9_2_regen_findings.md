## (c) Methodology confirmation -- matches the memo's stated approach

### 8.2 DSR

The 8.2 z-table in the memo was generated by `research/_rebaseline_dsr_both252.py`.
The regen reuses that script's machinery VERBATIM and swaps ONLY the CPM return
series to current prod. Confirmed identical:

| Element | Memo / generating script | Regen | Match |
|---|---|---|---|
| Expected-max null SR0 | Gumbel: `sqrt(V_trials)*((1-g)*z1 + g*z2)`, `g`=Euler-Mascheroni, `z1=ppf(1-1/N)`, `z2=ppf(1-1/(N*e))` | same | yes |
| Deflated z | `(SR_day - SR0_day)*sqrt(n-1) / sqrt(1 - skew*SR_day + ((exk+2)/4)*SR_day^2)` (PSR/DSR Lo-style non-normality denom) | same | yes |
| DSR | `norm.cdf(z)` | same | yes |
| N grid | 40, 80, 200, 500, 1000, 2000 | same | yes |
| V_trials (per-day) | 2.094e-5 (memo "measured input", std 0.073 ann) | 2.094e-5 (carried, see note) | yes |
| Daily SR_hat | `mean / std(ddof=1)` | same | yes |
| skew / excess kurtosis | `scipy.stats.skew` / `scipy.stats.kurtosis(fisher=True)` | same | yes |
| Monthly frame | month-end compounded, `V_m = V_trials*21` | same | yes |
| Window / n | clean 2008-05-30..2026-05-22, n=4524 | same | yes |

V_trials note: the memo treats `V_trials` (grid Sharpe variance across the
selection family) as a carried MEASURED constant, and its own generating script
hardcodes `2.094e-5` with the comment "grid family dispersion; ~unchanged under
both-252". V_trials is a property of the documented search grid, not of the single
winning config's daily returns, so it is held fixed exactly as the memo does.
Consequently SR0(N) is unchanged from the memo (SR0 depends only on V_trials and
N). Only the series-dependent inputs (SR_hat, skew, kurtosis) and therefore z/DSR
move. This is the faithful reproduction; inventing a new V_trials would be a
methodology change, not a rebaseline.

### 9.2 vol-window

Current prod CPM has exactly TWO volatility lookbacks (the old inverse-vol
weighting window is gone -- the risky block is now equal-weight):

1. rank-vol lookback -- `cpm_live.py` line ~464, hardcoded `.tail(252)` in the
   vol-adjusted Faber ranker `score = faber / vol_252`.
2. min-var covariance lookback -- `CORR_LOOKBACK_DAYS` (=252), `cpm_live.py`
   line ~485, used by `_min_var_subset` for the min-var 3-of-4 selection at
   n_pos=4.

The three configs are the current-prod analogues of the memo's three:

| Memo label (old) | Old meaning | Current-prod config | (rank_lb, cov_lb) |
|---|---|---|---|
| Production both-252 | rank252 / wt252 | both-252 (current prod) | (252, 252) |
| Split-window 252/504 | rank252 / wt504 (inv-vol) | split rank252 / cov504 | (252, 504) |
| Both-504 | rank504 / wt504 | both-504 | (504, 504) |

Methodology flag (semantics change): in OLD CPM the second window was the
inverse-vol WEIGHTING lookback (504). Current prod dropped inverse-vol weighting,
so the only non-ranking vol window is the min-var COVARIANCE lookback. The "split"
config therefore now means rank252 / cov504 (min-var covariance over 504d), which
is the faithful current-prod mapping of the old "split-window 252/504". Stated
explicitly so the change is not silent.

Bootstrap: paired stationary block bootstrap, same block index drawn for both
streams, percentile 95% CI, includes-zero test. B=2000, block=21, seed=42 to
match the memo's DECLARED convention (5.3, reused by the CI regen). The original
9.2 generating script (`cpm_volwindow_standardize_harness.py`) used B=5000; the
includes-zero conclusion was confirmed identical at both B=2000 and B=5000 (see
caveats), so the classification is robust to that choice.

Anchor verified through `cpm_harness.verify_anchor` (current prod both-252
Sharpe 1.255673, MaxDD -13.03%, Calmar 1.0076, n=4524) before any regen.
